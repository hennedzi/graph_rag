# Graph RAG: ETL + API + Harness

Локальный Graph RAG на русском: Qwen (LLM) + BGE-M3 (dense) + BM25 (sparse) + BGE-reranker-v2-m3 + Milvus.

| Файл | Что внутри |
|---|---|
| `core.py` | конфиг, логи, метрики, клиенты моделей, схема Milvus, гибридный поиск, генерация, верификация |
| `etl.py` | ETL (смонтирован в `api.py` под `/etl`): файл → чанки → триплеты (LLM) → эмбеддинги → upsert в Milvus; CLI `seed`/`reset` |
| `api.py` | единый сервер: `/etl/*`, `/search`, `/ask`, `/harness`, `/graph/*`, `/metrics/` |
| `harness.py` | агент с атомарными инструментами поверх графа; CLI для прогона вопросов |
| `cli.py` | терминальный клиент: полноэкранный TUI (curses) и построчный REPL, стриминг через `/harness/stream` |
| `graph.py` | граф в памяти: канонизация сущностей, Personalized PageRank, поиск путей; кэш сбрасывается после ETL |
| `eval.py` | прогон `eval/questions.jsonl` через harness → `runs/eval/<время>.json/.csv` (hit, шаги, токены) |
| `test_core.py`, `test_cli.py` | assert-тесты ядра и клиента (без моделей) |

## Запуск

1. Модели (как в AI_diplom):
   - LLM: Unsloth Studio, `unsloth/Qwen3.5-9B-GGUF:UD-Q4_K_XL` на `:8888` (для Harness включите tool calling)
   - эмбеддинги `bge-m3` на `:8001`, реранкер `bge-reranker-v2-m3` на `:8081` и Prometheus на `:9090`: `docker compose up -d`
     (модели скачиваются в `models/hf-cache` при первом запуске)
2. Конфиг: `cp config.example.ini config.ini` и впишите `api_key` из Unsloth Studio (`config.ini` в `.gitignore`).
   Температура LLM — там же: `temperature = 0.3` (0.0 — сухо и детерминированно; выше — развёрнутее формулировки).
   Зависимости: `uv sync` (создаст `.venv` по `pyproject.toml` + `uv.lock`)
3. Тесты: `uv run pytest -q test_core.py`. Новая зависимость: `uv add <пакет>`, dev: `uv add --dev <пакет>`
4. База — Milvus Lite (файл `graph_rag.db`). Файл открывает только один процесс, поэтому ETL смонтирован
   в основной сервер, а `uvicorn` запускается без `--workers`. CLI-команды (`etl.py seed/reset`, `harness.py`)
   запускайте при остановленном сервере.
5. Загрузить данные:
   ```bash
   uv run etl.py seed                                       # dataset.py, LLM не нужен; сервер остановлен
   uv run uvicorn api:app --port 8200
   curl -F files=@book.txt -F files=@notes.md localhost:8200/etl/documents   # → [{job_id,...}]
   curl localhost:8200/etl/jobs/<job_id>                    # queued → running → done|failed
   curl localhost:8200/stats                                # {"passage": N, "entity": N, "relation": N}
   ```
6. Спрашивать:
   ```bash
   curl -XPOST localhost:8200/ask     -H 'content-type: application/json' -d '{"query":"Кто был учителем Эйлера?"}'
   curl -XPOST localhost:8200/harness -H 'content-type: application/json' -d '{"query":"Кто был учителем Эйлера?"}'
   uv run cli.py                          # терминальный клиент (TUI), сервер должен быть запущен
   ```
7. Метрики: `localhost:8200/metrics/`; Prometheus: `localhost:9090` (поднимается тем же `docker compose up -d`).
8. Веб-интерфейс: `localhost:8200/ui/` (корень `/` редиректит туда). Собранный `web/dist` уже лежит в проекте,
   node нужен только чтобы менять фронтенд (см. «Веб-интерфейс»).

## ETL

- Форматы: `.txt`/`.md` (триплеты извлекает LLM), `.json` в формате `dataset.py` (триплеты готовые).
- Чанкинг: абзацы склеиваются до `chunk_chars`; длинный абзац режется по предложениям.
- Триплеты проходят валидацию: тип, пустые поля, длина, петли `s == o`, дубли; имена нормализуются (`ё→е`, регистр, пунктуация по краям).
- `id = sha1(содержимого)`. Повторная загрузка того же текста ничего не пишет и не тратит эмбеддинги.
- Новые документы дописывают `passage_ids` к уже существующим сущностям и отношениям (read-merge-write под lock). Эмбеддинги считаются только для новых строк.
- Ошибки сразу дают HTTP-ответ: 413 (размер), 422 (формат/кодировка/пустой файл). Ошибки моделей уходят в `status=failed` задачи.

## База знаний (`/etl/documents`)

| Запрос | Что делает |
|---|---|
| `GET /etl/documents` | документы: пассажи, сущности, связи, общие с другими документами сущности, дата, размер |
| `GET /etl/documents/{doc}` | пассажи по порядку чанков (с сущностями), связи и сущности документа |
| `DELETE /etl/documents/{doc}` | удаляет пассажи, у сущностей/связей вычищает ссылки на них; осиротевшие сущности и связи удаляются |
| `DELETE /etl/passages/{id}` | то же для одного неудачного чанка |

Повторная загрузка файла с тем же именем — замена: пассажи прошлой версии, которых нет в новой, вычищаются (`replaced` в задаче).
Дата, размер и порядок чанков хранятся в `documents.json` (`[etl] registry`), всё остальное — в Milvus.

## Поиск (`/ask`)

Кандидаты = пассажи сущностей ∪ пассажи отношений ∪ прямой гибридный поиск по пассажам → би-энкодер → реранкер → порог → генерация → верификация. Прямой поиск по пассажам добавлен как страховка на случай, когда сущность из вопроса не распознана.

## Harness (`/harness`)

Инструменты атомарные, каждый отдаёт несколько коротких строк:

| Инструмент | Что возвращает |
|---|---|
| `find_entities(query)` | нормализованные имена + число пассажей |
| `neighbors(entity, hops=1\|2)` | `s p o → [P1] [P4]`, связи отсортированы по близости к вопросу; `hops=2` добавляет связи соседей (multi-hop из [Graph RAG Milvus](https://milvus.io/docs/ru/graph_rag_with_milvus.md), но через фильтр `src in [...]` вместо матриц смежности); при неточном имени берётся ближайшая сущность |
| `query_db(kind, filter, query, count, k)` | прямой read-only запрос: булев фильтр Milvus (`like`, `in`, `text_match`, `array_contains`, `array_length`…) + опционально гибридный поиск внутри фильтра или `count`. Фильтр пишет сам агент ([подход Milvus](https://milvus.io/docs/ru/generating_milvus_query_filter_expressions.md)), шпаргалка по схеме лежит в описании инструмента. Белый список полей, хэндлы `"P3"` → id, ошибка Milvus с позицией уходит агенту на исправление (`harness_tool_calls_total{status="bad_query"}`) |
| `rank_by_ppr(entities, k=8)` | Personalized PageRank от 1–5 seed по всему графу ([HippoRAG](https://arxiv.org/abs/2405.14831)): топ сущностей и пассажей по массе — то, что важно для ответа, но не является прямым соседом |
| `find_paths(source, target, max_hops=3)` | цепочки связей между двумя сущностями (`a —pred→ b ←pred— c [P1]`) — для вопросов «как связаны X и Y»; короче и через менее «хабовые» вершины — выше |
| `search_passages(query)` | `[P#] score doc: превью` |
| `read_passage(ids)` | полный текст; повторное чтение возвращает «уже прочитан выше» |
| `answer(text, sources)` | ответ: `text` — связный текст без markdown; `sources` — список хэндлов `["P1", "P2"]`. Верификация проверяет утверждения по переданным источникам; неподтверждённые возвращаются агенту на исправление (`fix_rounds`) |

Реплики без вопроса не запускают поиск. «Спасибо», «привет», «понятно» отвечаются шаблоном без LLM (0 токенов);
«опиши проще», «короче», «своими словами» — одним вызовом LLM по прошлому проверенному ответу, ссылки на источники
сохраняются и проверяются верификатором, при провале отдаётся прошлый ответ (`route` в ответе: `agent` / `chat` /
`rewrite` / `rewrite_fallback`). Прочие не-вопросы агент закрывает `answer(reply=...)` за один шаг; на вопрос
(«?» или вопросительное слово) `reply` кодом не принимается — так агент не отвечает фактами без источников.

Финальный ответ: `answer(text="...", sources=["P1", "P2"])` — текст без markdown, источники в отдельном поле.
Код до LLM-верификатора отклоняет факт без источника и неизвестный хэндл, убирает markdown; `tool_choice = required` не даёт ответить мимо `answer` (если LLM-сервер его не умеет — один раз падаем на `auto`). В ответе `/harness` есть поле `claims` (структурированные утверждения с источниками) и `citations` (словарь хэндл → {doc_id, doc, text}).

Как экономится контекст: хэндлы `P#` вместо 34-символьных id, превью вместо текстов, полный текст только по запросу, общий бюджет окна `budget_tokens` (64000; автоматически урезается до `n_ctx` llama-server из `/props` минус 2048 под ответ; при остатке меньше четверти инструменты предупреждают агента). Окно считается по реальному `usage.prompt_tokens` от LLM (системный промпт, схемы инструментов, вся история) плюс оценка ~3 симв./токен для ещё не отправленных выводов. Ответ содержит `trace` (путь агента), `context_tokens` (окно сейчас), `tokens_spent` (prompt+completion за все шаги вопроса — это «счёт» за GPU), `context_chars`.

`search_passages` при отсутствии совпадений выше `min_rerank_score` не отвечает «ничего», а отдаёт до 3 слабых совпадений с пометкой — порог подбирался на одном корпусе и для технических доков (README, код) может быть завышен. `find_entities` подсказывает следующий шаг `neighbors(entity)`, чтобы агент шёл по графу, а не гадал хэндлы.

Диалог: ответ `/harness` содержит `session_id`; передайте его со следующим вопросом — агент продолжит ту же сессию
(история сообщений, хэндлы `P#`, прочитанные пассажи и подграф сохраняются, бюджет общий на диалог):

```
curl -XPOST localhost:8200/harness -H 'content-type: application/json' -d '{"query":"А кто пригласил его в Петербург?","session_id":"<id из прошлого ответа>"}'
```

В ответе `turn` (номер вопроса), `turn_chars` (выводы инструментов за этот вопрос), `context_tokens` (окно диалога), `budget`, `budget_left` (в токенах).
Когда бюджет кончился, инструменты отказывают и агент отвечает только по прочитанному — начните новый диалог (без `session_id`).
Неизвестная/истёкшая сессия или параллельный вопрос в той же сессии — `409`. Метрика `harness_followups_total`.

Канонизация: однословное имя склеивается с многословным, если полное имя с той же последней частью одно
(«эйлер» → «леонард эйлер»). Склейка только в графе в памяти, Milvus не меняется; `GET /graph/stats` показывает
граф до и после склейки и список псевдонимов. `POST /graph/explore {"entities": [...], "k": 15}` — PPR, пути
между первыми двумя seed и подграф.

## Оценка качества (`eval.py`)

```
uv run eval.py                                   # все вопросы из eval/questions.jsonl
uv run eval.py --only multi                      # только multi-hop
uv run eval.py --without rank_by_ppr,find_paths  # абляция: агент без новых инструментов
```

Строка вопроса: `{"q": "...", "expect": ["подстрока", ...], "type": "single|multi"}`. `hit` — все ожидаемые подстроки
есть в ответе (без регистра). В файл пишется git-коммит — запуски до/после изменения можно сравнить.

## Метрики

| Метрика | Зачем |
|---|---|
| `rag_stage_seconds{stage}` | латентность каждого этапа: embed, hybrid_search, rerank, generation, verification, graph_build, etl_*, tool_* |
| `rag_llm_tokens_total{kind}` | расход токенов prompt/completion |
| `rag_model_errors_total{kind}` | недоступность моделей, невалидный JSON верификатора |
| `rag_requests_total{endpoint,outcome}` | answered / unsupported / no_context / error |
| `rag_top_rerank_score`, `rag_passages_used` | качество retrieval: если score проседает, значит база не покрывает вопросы |
| `rag_unsupported_claims_total`, `harness_unsupported_claims_total` | галлюцинации |
| `etl_documents_total{status}`, `etl_chunks_total`, `etl_rows_written_total{type}` | объём загрузки |
| `etl_triples_total{result}` | accepted / duplicate / rejected_format / rejected_value / rejected_json — качество экстрактора |
| `etl_jobs_in_progress` | очередь ETL |
| `harness_tool_calls_total{tool,status}`, `harness_steps`, `harness_context_chars`, `harness_context_tokens`, `harness_tokens_spent`, `harness_answers_total{outcome}` | поведение агента и экономия контекста |

PromQL:
```promql
histogram_quantile(0.95, sum by (le, stage) (rate(rag_stage_seconds_bucket[5m])))      # p95 по этапам
sum(rate(rag_requests_total{outcome="unsupported"}[1h])) / sum(rate(rag_requests_total[1h]))  # доля галлюцинаций
sum by (result) (rate(etl_triples_total[1h]))                                            # качество экстракции
histogram_quantile(0.5, rate(harness_context_chars_bucket[1h]))                          # медиана контекста агента
```

## Терминальный клиент (`cli.py`)

Полноэкранный клиент на `curses` (stdlib, без зависимостей) поверх того же API; построчный REPL — fallback для pipes и логов.

```
uv run cli.py                              # TUI (сервер должен быть запущен на :8200)
uv run cli.py "Кто был учителем Эйлера?"   # один вопрос без REPL
uv run cli.py --no-tui                     # построчный REPL
uv run cli.py --doc README.md -q           # поиск по документу, без шагов
uv run cli.py --url http://host:8200       # другой адрес (или RAG_URL)
uv run cli.py --mode ask "вопрос"          # классический /ask вместо агента
```

Хоткеи: `F1` справка, `F2` новая сессия, `F3` последние запуски, `F4` выбрать документ, `F5` стрим вкл/выкл, `F10` выход, `PgUp/PgDn` листать ленту, `Enter` отправить, `Ctrl+C` очистить строку или остановить запрос (`/harness/stop`). Диалог продолжается: `session_id` из ответа прокидывается в следующий вопрос. Команды: `/new`, `/doc`, `/mode`, `/runs`, `/run`, `/stats`, `/help`, `/exit`.

Клиент ходит только в API и не знает про модели.

## Веб-интерфейс (`web/`)

React + Vite + shadcn/ui + Recharts + d3-force. FastAPI отдаёт собранный `web/dist` на `/ui/`; API не меняется.

Раскладка как в IDE (Zed / VS Code / Claude Code): слева панель активности (Ctrl/⌘+1…5 — разделы, переключатель темы),
затем боковая панель (Ctrl/⌘+B), центр, инспектор справа (Ctrl/⌘+Alt+B), внизу строка состояния (здоровье API,
счётчики Milvus, сводка текущей страницы). Ширины панелей тянутся мышью и запоминаются; на узком экране боковые панели скрываются.

- **Harness** — слева диалоги вкладки и история запусков, в центре компактная лента шагов (как в Claude Code: строка на шаг,
  клик раскрывает результат), справа инспектор с вкладками Граф / Шаг / Источники / Сводка. Живой ход агента через `POST /harness/stream` (SSE): мысли, вызовы инструментов с аргументами и
  результатами, бюджет контекста, растущий подграф связей, финальные утверждения с источниками (наведение на `P#` — текст пассажа).
- **Граф** — PPR от выбранных сущностей (размер вершины — масса), пути между первыми двумя (клик подсвечивает путь), таблица ранжирования и пассажи; клик по вершине добавляет её в seed.
- **Поиск** — слева список запросов, справа retrieval; `/search` (сущности, связи, пассажи со score реранкера) рядом с `/ask`.
- **Документы** — библиотека: поиск по документам, карточка документа (пассажи с сущностями, связи, сущности → граф), замена новой версией, удаление документа или пассажа (подтверждение вторым кликом), очередь ETL. Тема по умолчанию светлая, выбор запоминается.
- **Метрики** — графики из `GET /dashboard` (снимок Prometheus-метрик в JSON) и `GET /runs` (история `runs/*.json`).

Разработка фронтенда (API должен быть запущен на :8200, dev-сервер проксирует запросы):

```
cd web
npm install
npm run dev
```

Пересобрать то, что отдаёт FastAPI: `cd web && npm run build`.

События `/harness/stream` (`data: {json}` на строку): `start`, `thought`, `call`, `result` (status, out, chars, ms,
total_chars, edges), `done` (полный результат как у `/harness`), `error`.

## Что упрощено (ponytail)

Из исходника убраны: обёртки `step/info/ok/warn/banner` (заменены на `logging`), неиспользуемые `min_entity_score`/`min_entities_keep`, ручной парсинг markdown-JSON (теперь один `parse_json`), auto_id (заменён хэшем, без него невозможна идемпотентная дозагрузка).

Сознательно не сделано, при необходимости добавляется отдельно:
- PDF/DOCX: сейчас только txt/md/json;
- канонизация только по фамилии; синонимы и опечатки (по эмбеддингам) не склеиваются;
- контекст соседних чанков при извлечении триплетов: местоимения на границе чанков теряются;
- статусы задач ETL хранятся в памяти; при рестарте теряются, но повторная загрузка безопасна;
- `/harness/stream`: если закрыть вкладку, агент доработает в фоне и сохранит run (отмены по disconnect нет);
- сессии диалога хранятся в памяти процесса (TTL 1 ч, до 100 штук): при рестарте теряются, с `--workers` > 1 не работают;
- `/dashboard` показывает счётчики текущего процесса: после рестарта они с нуля, история — в `runs/` и Prometheus;
- один процесс (Milvus Lite + lock на процесс). Переход на Milvus standalone: `uri = http://localhost:19530`,
  схема и код те же, ETL можно снова вынести: `uvicorn etl:app --port 8100`.
