## Цель
Независимые вызовы инструментов (`search_passages`, `neighbors`, `rank_by_ppr`) выполняются одновременно,
а не по очереди. Три вызова по 300 мс должны занимать 300 мс, а не 900. Также гибридный поиск
(dense + sparse/BM25) уходит в Milvus одним запросом `hybrid_search` с RRF-фьюженом.

## Контекст: где это в коде
- `harness.py` — цикл агента: модель может вернуть несколько tool calls за один ход,
  сейчас они выполняются последовательно.
- `core.py` — поисковое ядро: векторный и полнотекстовый поиск сейчас отдельные вызовы Milvus.
- `graph.py` — `neighbors`, `find_paths`, `rank_by_ppr`; `rank_by_ppr` зависит от entities из поиска,
  то есть НЕ независим.
- `test_core.py` — сюда добавить тесты.

## Что сделать
1. В `harness.py` вынеси диспетчеризацию: если модель вернула N вызовов инструментов за один ход —
   определи независимые (нет передачи результата одного в аргументы другого) и выполни их через
   `asyncio.gather`. Зависимые вызовы оставь последовательными.
2. В `core.py` замени пару «векторный поиск + полнотекстовый поиск» на один `hybrid_search`
   Milvus с `RRFRankер` (или `WeightedRanker`) — оба канала в одном запросе.
3. Каждому параллельному вызову — своё событие `tool_call` с `started_at` из C8: у параллельных
   вызовов `started_at` должен совпадать, `duration_ms` — нет.
4. В `test_core.py`: тест, что два независимых инструмента имеют одинаковое `started_at`;
   тест, что `hybrid_search` возвращает объединённый список с dedup по `passage_id`.

## Границы задачи
- Не делай параллельным `rank_by_ppr` после `search_passages` — он использует entities из результата.
- Не меняй промпты агента и логику выбора инструментов.
- Не добавляй префетч — это C3.

## Как проверить
```
uv run pytest -q test_core.py
```
Затем два одинаковых вопроса «до/после» и сравнение p95 из сводки C8 по типу tool_call.

- [ ] В трассе run независимые вызовы имеют совпадающий `started_at`.
- [ ] Общее время run на тестовом вопросе не выросло, по сводке C8 видно сокращение.
- [ ] Все тесты зелёные.
