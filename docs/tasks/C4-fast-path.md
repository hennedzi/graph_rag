# C4. Быстрый путь по порогу уверенности

## Цель
Расширить существующие быстрые сценарии («спасибо», «пересказ прошлого ответа») до общего правила:
если после первого поиска скор реранкера топ-пассажей выше порога — маленькая модель отвечает сразу,
без графа и без второго круга рассуждений. Глубокий путь — только если быстрый не набрал уверенности.

## Контекст: где это в коде
- `harness.py` — уже есть ветка быстрых ответов по словарю слов («спасибо», «опиши проще»);
  сюда же встроена проверка «ответил ли на вопрос». Рядом — цикл с решением «искать глубже».
- `core.py` — реранкер: возвращает скоры, порога сейчас нет.
- Сводка C8 — источник данных о том, сколько шагов тратит типовой вопрос.

## Что сделать
1. В `core.py` после реранкинга верни топ-скор (или убедись, что он уже возвращается).
2. В `harness.py` после первого поиска: если `top_score >= FAST_PATH_THRESHOLD` — один вызов LLM
   «ответь на вопрос по этим пассажам с цитатами» и завершение. Порог — константа в конфигурации,
   начни с 0.8 (если скоры в [0,1]) — уточни по фактическому диапазону скоров своего реранкера.
3. В трассу запиши событие `{"type": "fast_path_taken", "top_score": ...}`.
4. Порог вынеси в конфиг, не хардкод в логике.
5. Тест: вопрос с заведомо релевантным пассажем (по тестовой базе) идёт быстрым путём за один шаг LLM;
   вопрос без релевантных — уходит в глубокий путь.

## Границы задачи
- Не трогай глубокий путь: граф, `find_paths`, несколько кругов — как были.
- Не добавляй новых вызовов LLM сверх одного.
- Порог не подгоняй под тесты: сначала посмотри распределение скоров в `runs/`.

## Как проверить
```
uv run pytest -q test_core.py
```
По сводке C8: доля вопросов, закрытых за <= 1 шага LLM, и сравнение p95 быстрого и глубокого пути.

## Критерии готовности
- [ ] Релевантные вопросы отвечают за один шаг LLM.
- [ ] Событие `fast_path_taken` видно в ленте.
- [ ] Качество не падает — проверить на вопросах из D1.
