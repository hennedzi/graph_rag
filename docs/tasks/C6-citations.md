## Цель
Предложения ответа содержат маркеры `[1]`, `[2]`, где номер — `passage_id` найденного фрагмента.
Клик по маркеру открывает пассаж в правой панели и подсвечивает его. Это главный пробел
прозрачности: переход «утверждение в ответе → фрагмент документа».

## Контекст: где это в коде
- `harness.py` — финальная генерация ответа; здесь формируется промпт с найденными пассажами.
- `core.py` — результаты поиска: список пассажей с `passage_id`.
- `web/src/pages/Harness` — рендер ответа и правая панель источников.

## Что сделать
1. В `harness.py` в промпт финального ответа добавь правило: каждое утверждение заканчивать
   маркером `[n]`, где n — порядковый номер пассажа в переданном списке. Передавай списком:
   «[1] passage_id=... | [2] passage_id=...».
2. После генерации проверь ответ регуляркой `\[(\d+)\]`: каждый упомянутый номер должен
   существовать в списке. Несуществующие — удалить или заменить на ближайший существующий.
3. Сохрани соответствие «номер → passage_id» в событии ответа (поле `citations`).
4. В `web/src` отрендери маркеры как кнопки. Клик: подгрузить пассаж из `citations`,
   показать в правой панели, подсветить текст пассажа. Если пассаж принадлежит документу
   из раздела Документы — ссылка на карточку документа.
5. Тест в `test_core.py`: генерация с фиксированными пассажами даёт ответ, все маркеры
   которого разрешаются в `citations`.

## Границы задачи
- Не стримь токены ответа — это C5; цитаты должны работать и на готовом тексте.
- Не меняй логику поиска и ранжирования.
- Рёбра графа в подсветку не добавляй — только пассаж, отдельная задача.

## Как проверить
```
uv run pytest -q test_core.py
cd web && npm run build
```
В браузере: вопрос, клик по каждому маркеру в ответе.

## Критерии готовности
- [ ] Каждый маркер в ответе разрешается в реальный `passage_id`.
- [ ] Клик показывает и подсвечивает фрагмент.
- [ ] Ответ без источников не содержит маркеров.
