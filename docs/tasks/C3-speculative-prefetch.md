## Цель
При получении вопроса сразу, до первого вызова LLM, вычислить эмбеддинг и запустить гибридный поиск
в фоне. Если агент решит искать — результат берётся из кэша; промах — просто отбрасывается.
На корректность не влияет, средний выигрыш — один полный round-trip поиска.

## Контекст: где это в коде
- `api.py` — `POST /runs`: здесь стартует run; фоновая задача запускается здесь же.
- `core.py` — эмбеддинг вопроса и `hybrid_search` (после C2 — один вызов).
- `harness.py` — цикл агента: решение «искать» принимает модель; кэш проверяется при вызове
  `search_passages`.
- Кэш из C7 (сделай C7 раньше или одновременно).

## Что сделать
1. В `api.py` при создании run запускай `asyncio.create_task` на префетч:
   `embedding(question)` + `hybrid_search(...)`, результат — в кэш C7 c ключом `question`.
2. В `harness.py` перед вызовом `search_passages` проверь кэш; при попадании используй результат
   и пометь событие: `"speculative": true` (обязательно — иначе прозрачность ломается).
3. При промахе префетча (агент не искал) — просто не использовать результат, ничего не чистить.
4. TTL результата — тот же, что у кэша C7.
5. Тест: run с префетчем отвечает быстрее и содержит `speculative: true` в tool_call.

## Границы задачи
- Не префетчь графовые вызовы (`neighbors`, `find_paths`) — только гибридный поиск.
- Не префетчь уточняющие реплики диалога — только новый вопрос.
- Без пометки `speculative` задачу считать невыполненной.

- [ ] Hit rate виден в `runs/`.
