## Цель
Фиксированный набор вопросов (30–50) прогоняется в трёх конфигурациях, оценка — LLM-judge,
а не проверка подстрок. Результат — таблица «правильность / отказы / p50 / p95 / шаги» —
ядро экспериментальной части диплома и способ настроить порог C4.

## Контекст: где это в коде
- `eval.py` — сейчас оценивает попадание по подстрокам; нужен новый режим, старый не удаляй.
- `runs/` — источник латентности и шагов (сводка C8).
- `harness.py` — конфигурации запуска.

## Что сделать
1. Составь файл `eval/questions.json` — 30–50 вопросов по твоей базе документов:
   треть фактовых (один пассаж), треть связующих (нужен граф, связи между сущностями),
   треть без ответа в базе (правильное поведение — «не знаю»).
2. Три конфигурации запуска: (a) чистый гибридный поиск без агента, один вызов;
    (b) текущий агент гибрид+граф; (c) быстрый путь C4.
3. Оценка LLM-judge: промпт судье — «вопрос, эталонный признак ответа, ответ системы;
    оцени: отвечает ли, полнота, обоснованный ли отказ». Судья — модель побольше,
    не та, что в системе. Шкала 0–2 (нет / частично / да) + краткое обоснование.
4. Сводка: по каждой конфигурации правильность, отказы (в т.ч. ложные «не знаю»),
   p50/p95, среднее число шагов LLM из C8.
5. Отчёт в `runs/eval_report.md`: таблица + 5 самых показательных расхождений между (a) и (b).

## Границы задачи
- Не заменяй eval подстрок полностью — оставь как дешёвую проверку регрессий.
- Судья не должен видеть, из какой конфигурации ответ.
- Не подгоняй вопросы под успех конфигурации (b) — набор фиксируется до запуска.

## Как проверить
Прогон всех трёх конфигураций на полном наборе вопросов, отчёт существует и заполнен.

## Критерии готовности
- [ ] Таблица по трём конфигурациям заполнена.
- [ ] Есть кейсы, где граф помог, и кейсы, где не помог.
- [ ] Порог C4 при необходимости переоценён по результатам.
