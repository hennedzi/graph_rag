## Цель
События run (уже пишутся в журнал с `run_id` и `seq`) отображаются в ленте Harness по мере появления,
а не после завершения run. Это главный источник ощущения скорости: пользователь видит прогресс каждые
сотни миллисекунд вместо пустого экрана.

## Контекст: где это в коде
- `harness.py` — цикл агента, события создаются здесь (после каждого шага LLM/инструмента).
- `api.py` — FastAPI-эндпоинты, запуск `POST /runs`, выдача сохранённых events.
- `web/src/pages/Harness` — лента сообщений и инспектор справа; сейчас данные приходят опросом.

## Что сделать
1. В `harness.py` добавь в функцию запуска run необязательный параметр `emit` (callback или
   `asyncio.Queue`). Каждый раз, когда событие пишется в журнал, дублируй его в `emit`.
2. В `api.py` при `POST /runs` создавай очередь, привязывай её к run, и открой новый эндпоинт:
   `GET /runs/{run_id}/events/stream` — `StreamingResponse` с `media_type="text/event-stream"`.
   Формат кадра: `data: {json события}\n\n` (одно событие — один кадр).
3. Закрывай поток по завершении run посылкой события `{"type": "run_finished"}`.
4. В `web/src/pages/Harness` замени опрос на `EventSource('/runs/{run_id}/events/stream')`.
   Новые события рендерь инкрементально в конец ленты. При `run_finished` — закрывай соединение.
5. Прогрессивное раскрытие в ленте: каждое событие — одна строка-сводка
   («Гибридный поиск — 12 фрагментов, 340 мс»). Полные поля события — в инспекторе справа
   (по клику на строку). События типа «ошибка» и «не знаю» — всегда развёрнуты.
6. Тест в `test_core.py`: при запуске run с подключённой очередью все события доходят
   в порядке `seq`.

## Границы задачи
- Не меняй схему событий: те же `run_id`, `seq`, `type`, плюс `duration_ms` из C8.
- Не трогай страницы Документы и Граф.
- Не стримь токены ответа — это C5, здесь только события.

## Как проверить
```
uv run pytest -q test_core.py
cd web && npm run build
uvicorn api:app --reload   # затем в другом терминале:
curl -N http://localhost:8000/runs/<run_id>/events/stream
```
В браузере: запусти вопрос в Harness, события должны появляться до окончания ответа.

## Критерии готовности
- [x] Первое событие появляется в ленте < 500 мс после старта run.
- [x] Порядок событий соответствует `seq`.
- [x] Разрыв соединения не ломает run (журнал продолжает писаться).
